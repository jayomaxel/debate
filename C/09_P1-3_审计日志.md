# P1-3 审计日志

## 本轮目标

建立统一审计事件入口，覆盖登录、刷新、登出、配置修改、上传网关、限流和 ws ticket 等安全关键动作，并提供查询接口。

## 修改文件

- `api/services/audit_service.py`
- `api/utils/security.py`
- `api/routers/auth.py`
- `api/routers/admin.py`
- `api/routers/websocket.py`
- `api/tests/test_audit_service.py`

## 代码逻辑

- 在 `api/services/audit_service.py` 建立 `AuditService.record_event()`：
  - 统一生成 `AuditLogEventContract`
  - Redis 列表优先持久化
  - Redis 不可用时退化到进程内缓存
  - 同时写入 Prometheus 计数
- 在 `api/utils/security.py` 提供合同 builder，保证审计事件字段结构一致。
- 在 `api/routers/auth.py`、`api/routers/websocket.py`、`api/routers/admin.py` 接入审计点，覆盖：
  - 登录成功/失败
  - refresh 成功/失败
  - logout / logout-all
  - ws ticket 签发
  - 配置修改
  - 管理员密码修改
- 在 `api/routers/admin.py` 新增 `GET /api/admin/audit/events`，用于管理员查询事件列表。
- 在 `api/tests/test_audit_service.py` 验证 Redis 降级、事件写入和查询行为。

## 对应功能

- 审计字段不再散落在不同业务里各自拼装。
- 管理端可以统一查看关键安全动作。
- Redis 不可用时，审计功能不会直接失效为 500。

## 风险/未完成项

- 当前是最小可上线实现，没有接入长期归档、检索索引或外部 SIEM。
- 进程内降级缓存适合短期兜底，不适合跨实例持久保存。

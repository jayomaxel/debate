# C5 报告与候选题限流审计补齐迭代总结

## 本轮目标

- 补齐报告生成/重新生成路径的限流覆盖。
- 为候选辩题生成预置限流策略，避免后续接口新增后缺少保护。
- 在报告 PDF 生成和报告邮件发送成功后记录审计事件。

## 修改文件

- `api/middleware/rate_limit.py`
- `api/routers/student.py`
- `api/tests/test_rate_limit.py`
- `api/tests/test_student_report_pdf_cache.py`

## 代码逻辑

- `report_regeneration` 限流策略改为覆盖 `GET/POST/PUT`，并明确匹配 `/reports/{id}/export/pdf`、`/reports/{id}/export/excel`、`/reports/{id}/send-email`。
- 新增 `candidate_topic_generation` 限流桶，覆盖 `/api/teacher/topics/generate`、`candidate-topics`、`topic-candidates`、`debate-topics/generate` 等候选辩题生成常见路径。
- `student.py` 新增 `_record_report_generation_audit`，统一写入 `report_regeneration` 审计事件。
- PDF 真正渲染并写入缓存后记录 `export_report_pdf` 审计，包含是否生成 markdown、是否生成 PDF、PDF 文件名。
- 报告邮件发送成功后记录 `send_report_email` 审计，包含是否生成 markdown 和接收用户。
- PDF 缓存命中判断前移：已有 `report_pdf` 或默认报告 PDF 路径存在时，直接返回缓存，避免先重算 markdown 导致无发言场景误 404。

## 对应功能

- 报告导出、报告邮件和未来候选题生成都有基础限流保护。
- 触发报告生成/交付的操作具备可追溯审计事件。
- 已存在 PDF 缓存的报告导出更稳定，不会重复触发生成链路。

## 验证结果

- `python -m pytest api\tests\test_rate_limit.py -q`：5 passed。
- `python -m pytest api\tests\test_student_report_pdf_cache.py -q`：3 passed。
- `python -m pytest api\tests\test_audit_service.py -q`：5 passed。

## 风险与说明

- 当前候选辩题生成接口在代码中尚未实际存在，本轮采取中间件预置策略；真实接口落地时，只要路径落在策略范围内就会自动受限。
- 如果未来候选题接口命名完全不同，需要把新路径补进 `candidate_topic_generation` 的正则。

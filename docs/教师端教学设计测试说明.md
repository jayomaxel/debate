# 教师端教学设计功能测试说明

## 1. 测试目标

验证教师从“上传教学设计”到“生成并采用候选辩题”、创建普通/预约辩论、查看历史版本及课后能力雷达图的完整链路，重点确认：

- PDF/DOCX 上传、文本抽取、缺失字段提示及人工校正可用；
- 候选辩题确实关联当前教学设计版本与本次教学重点；
- 模型不可用时可降级，教师仍可手动输入辩题；
- 历史辩论保留创建时使用的教学设计版本，不随当前版本切换而改变；
- 能力雷达图只统计真实人类学生的有效发言与有效评分。

## 2. 测试前准备

1. 执行数据库迁移至 `015`。
2. 准备教师账号、两个归属该教师的班级，以及至少两名真实学生账号。
3. 准备以下文件：
   - 完整的 PDF 教学设计（小于 10MB）；
   - 完整的 DOCX 教学设计（小于 10MB）；
   - 缺少“课时约束、教师备注”的教学设计；
   - 扫描版无文本 PDF；
   - 超过 10MB 的文件；
   - 非 PDF/DOCX 文件。
4. 完整样例至少包含：课程目标、知识点、章节主题、重点难点、能力培养目标、适用年级、课时约束、教师备注。
5. 分别准备“模型配置正常”和“模型不可用/无 API Key”两种环境。

## 3. 核心业务链路

```text
选择班级
  → 上传 PDF/DOCX
  → 查看抽取状态、置信度、缺失项和抽取依据
  → 教师人工校正并保存
  → 填写本次章节重点/训练目标/课堂场景
  → 生成、查看依据并采用候选辩题（或手工输入）
  → 创建普通辩论或预约辩论
  → 完成辩论与评分
  → 教师查看仅含真实学生的能力雷达图
```

## 4. 页面功能测试用例

| 编号 | 场景与操作 | 预期结果 |
|---|---|---|
| TD-01 | 进入教师端“教学设计”，选择班级 | 展示该班级当前版本；无版本时显示明确空状态 |
| TD-02 | 上传合法 PDF | 上传成功，生成 V1，状态为“可使用”或“待校正”，文件名、置信度、字段和依据可见 |
| TD-03 | 上传合法 DOCX | 与 PDF 一致；表格中的文字也能参与抽取 |
| TD-04 | 上传缺字段文件 | 缺失字段被明确列出，不以虚构内容补齐；状态为“待校正” |
| TD-05 | 修改抽取结果并保存 | 保存成功；`effective_data` 使用教师校正值，原始抽取结果仍保留 |
| TD-06 | 上传同班级第二份文件 | 生成 V2 并自动成为当前版本；V1 仍在历史列表 |
| TD-07 | 将 V1 设为当前版本 | V1 变为当前，V2 保留；创建页随后读取 V1 |
| TD-08 | 切换到另一个班级 | 只展示目标班级的版本，不串班、不沿用原班级活动重点 |
| TD-09 | 上传空文件、非支持格式、超过 10MB 文件 | 前后端均拒绝并显示可理解错误，不产生可用版本 |
| TD-10 | 上传扫描版无文本 PDF | 版本显示“抽取失败”及原因；不可保存校正或生成推荐，可重新上传/切换历史版本 |
| TD-11 | 非本班教师访问版本接口 | 返回 403，不泄露文件内容、抽取文本或版本信息 |
| TP-01 | 当前班级无教学设计时进入创建页 | 显示“未配置教学设计”；推荐按钮不可用，但手工辩题仍可填写 |
| TP-02 | 填写章节重点、训练目标、课堂场景并生成 | 返回候选题；每题显示难度、推荐理由、课程目标/知识点映射及可辩性依据 |
| TP-03 | 点击“采用该题” | 辩题写入可编辑输入框；教师可再次人工修改 |
| TP-04 | 点击“重新生成” | 旧候选被新结果替换，页面不重复提交、不丢失当前教学重点 |
| TP-05 | 模型不可用时生成 | 返回规则降级候选并明确提示，不阻塞手动创建 |
| DB-01 | 使用推荐题创建普通辩论 | 创建成功；详情中的 `config_meta` 保存教学模式、版本 ID、活动重点、轮数等 |
| DB-02 | 使用推荐题创建预约辩论 | 创建成功；预约详情同样保存教学设计版本和活动重点 |
| DB-03 | 编辑已有辩论 | 页面回显其创建时的版本 ID 与活动重点；保存后结构化配置仍存在 |
| DB-04 | 创建后切换班级当前教学设计 | 已创建辩论仍指向原版本，历史记录不被当前版本覆盖 |

## 5. 能力雷达图专项用例

| 编号 | 数据准备 | 预期结果 |
|---|---|---|
| RD-01 | 两名真实学生均有有效发言和评分，另有 AI 发言 | 标题为“人类辩手核心能力评估”；AI 不进入五维均分、综合分、排名或人数 |
| RD-02 | 学生 A 有两条 40/60 分发言，学生 B 有一条 100 分发言 | 先得 A=50、B=100，再按学生等权汇总为 75；不得按三条发言算 66.67 |
| RD-03 | 仅有 AI 发言 | 雷达图为空态，五维值和综合分显示 `--`/空，不显示 0 |
| RD-04 | 学生发言为空、无效、转写失败或缺少关联评分 | 该发言不进入雷达图，并且不增加有效发言数 |
| RD-05 | AI 与人类均有计时数据 | 发言时长图可同时展示人类和 AI；能力雷达仍只统计人类 |
| RD-06 | 教师选择某个 AI 辩手 | 明确提示 AI 评分不参与人类能力评估，不展示伪造雷达值 |

五维字段映射必须固定为：

| 后端评分字段 | 教师端能力名称 |
|---|---|
| `logic_score` | 逻辑建构 |
| `argument_score` | AI 核心知识运用 |
| `response_score` | 批判思维 |
| `persuasion_score` | 语言表达 |
| `teamwork_score` | AI 伦理科技素养 |

## 6. 接口检查

| 方法 | 路径 | 检查点 |
|---|---|---|
| GET | `/api/teacher/classes/{class_id}/teaching-designs` | 版本按版本号倒序；只返回可访问班级 |
| GET | `/api/teacher/classes/{class_id}/teaching-designs/current` | 返回唯一当前版本；无数据返回 `null` |
| POST | `/api/teacher/classes/{class_id}/teaching-designs` | multipart 上传；格式和 10MB 限制；生成新版本 |
| PUT | `/api/teacher/teaching-designs/{version_id}` | 只允许已知结构字段；保存校正值而不覆盖原始抽取值 |
| POST | `/api/teacher/teaching-designs/{version_id}/activate` | 同班级其他版本取消当前状态 |
| POST | `/api/teacher/classes/{class_id}/topic-recommendations` | 版本必须属于该班级；失败版本返回 409；返回生成来源 |

## 7. 数据库检查

检查 `class_teaching_designs`：

- `(class_id, version_number)` 唯一；
- 同一班级正常情况下只有一个 `is_active=true`；
- `extracted_data` 与 `corrected_data` 分开保存；
- `missing_fields`、`confidence`、`source_excerpt_map` 可追溯；
- 辩论的房间元数据中包含 `debate_config_meta.teaching_design_version_id` 与 `activity_focus`。

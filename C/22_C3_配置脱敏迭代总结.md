# C3 配置脱敏迭代总结

## 本轮目标

补齐截图反馈中的 C3：模型、ASR、TTS、Coze、Vector 不再在管理端真实接口中返回明文 `api_key` / `api_token`，并保持邮件密码脱敏逻辑一致。

## 修改逻辑

- `api/services/config_service.py`
  - 新增统一脱敏合同构造入口。
  - 更新配置时识别“前端原样提交 masked 值”的情况，避免把脱敏字符串覆盖成真实密钥。
  - 模型、ASR、TTS、Coze、Vector、Email 更新逻辑都复用 `resolve_secret_update`。
- `api/routers/admin.py`
  - 为六类配置分别增加 `_build_*_config_response`。
  - GET 和更新接口都返回脱敏后的 `api_key` / `api_token` / `smtp_password_masked`。
  - 每个响应都带统一 `secret` 字段：`configured`、`masked`、`updated_at`、`updated_by`。
- `api/tests/test_config_masking.py`
  - 覆盖模型、ASR、TTS、Vector、Coze、Email 六类真实接口。
  - 验证响应字符串中不包含原始 secret。
  - 验证提交 masked 值不会破坏后端真实密钥。

## 对应功能

- 管理端可以判断密钥是否已配置，但拿不到明文密钥。
- 前端表单可以展示 masked 值；用户不改密钥时，后端保留原始 secret。
- 截图中指出的 `api/routers/admin.py` 明文返回点已经统一改为脱敏返回。

## 验证结果

```bash
python -m pytest api/tests/test_config_masking.py -q
```

结果：`9 passed`。

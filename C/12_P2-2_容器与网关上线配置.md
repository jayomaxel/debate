# P2-2 容器与网关上线配置

## 本轮目标

补齐开发和生产的容器配置、前端网关和镜像构建脚本，让工作包 C 的安全能力可以随着完整系统一起拉起和验收。

## 修改文件

- `docker-compose.yml`
- `docker-compose.dev.yml`
- `Dockerfile.api`
- `Dockerfile.web`
- `web/nginx.conf`

## 代码逻辑

- `docker-compose.yml`
  - 从原先只含 `api/web` 的简版，扩展为 `db/redis/api/web` 全链路部署。
  - 生产环境下只对外暴露 `web` 端口，`api` 改成容器内暴露。
  - `api` 启动前先执行 `alembic upgrade head`。
- `docker-compose.dev.yml`
  - 去掉 `network_mode: host`。
  - `web` 改为标准端口映射 `127.0.0.1:8860:8860`。
  - 注入 `VITE_DEV_API_PROXY_TARGET` 和 `VITE_DEV_WS_PROXY_TARGET`，让本地 Vite 代理直连容器内 API。
- `Dockerfile.api`
  - 增加默认生产运行标志 `ENVIRONMENT=production` 和 `DEBUG=false`。
  - 创建上传隔离目录 `uploads/quarantine`。
- `Dockerfile.web`
  - 构建阶段改为 `pnpm build`，让前端类型错误和构建错误在镜像构建时直接失败。
  - 健康检查切到 `/healthz`。
- `web/nginx.conf`
  - 增加基础安全头。
  - 增加 `client_max_body_size 12m`。
  - 新增 `/healthz`。
  - 代理 `/metrics`，并限制为本机或私网访问。
  - 修正 API、上传、文档和 WebSocket 的反向代理头部。

## 对应功能

- 开发环境和生产环境都能按统一思路启动。
- 网关具备更明确的健康检查、安全头和上传体积限制。
- 前端镜像构建不再绕过类型检查。
- API 不再默认直接暴露到公网。

## 风险/未完成项

- 生产 compose 仍使用仓库内的 `Dockerfile.db.local` 作为 PostgreSQL 基础镜像，正式上线前应确认是否满足运维规范。
- `/metrics` 的访问控制是网关级最小实现，正式公网部署时仍建议叠加防火墙或内网采集。

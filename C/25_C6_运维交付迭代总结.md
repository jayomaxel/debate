# C6 运维交付迭代总结

## 本轮目标

补齐截图反馈中的 C6：在已有 health、Docker、nginx 基础上补 `/metrics`、CI workflow、部署/备份/安全文档和部署环境变量强制校验。

## 修改逻辑

- `api/main.py`
  - 增加 Prometheus 指标：
    - `debate_database_up`
    - `debate_redis_up`
    - `debate_redis_enabled`
    - `debate_service_start_time_seconds`
    - `debate_service_info`
  - 暴露 `/metrics`。
  - `/health` 与 `/api/health` 刷新运行态指标。
- `api/tests/test_health_check.py`
  - 补充 metrics 最小验证，确认指标文本包含核心运行态指标。
- `Dockerfile.api`、`Dockerfile.web`
  - 固定生产运行环境标志。
  - 前端镜像改为 `pnpm build`，让类型和构建错误在镜像构建期暴露。
  - 增加健康检查与上传隔离目录。
- `docker-compose.yml`、`docker-compose.dev.yml`
  - 生产 compose 明确 `db/redis/api/web` 拓扑。
  - 主 compose 要求部署变量显式传入。
  - 开发 compose 使用标准端口映射和 Vite 代理变量。
- `web/nginx.conf`
  - 增加 `/healthz`。
  - 增加安全响应头。
  - 代理 `/metrics` 并限制为本机/私网访问。
  - 修正 API、uploads、docs、WebSocket 反向代理头。
- `.github/workflows/ci.yml`
  - 新增后端 C 包测试 job。
  - 新增前端 type-check 与 build job。
- `ops/`
  - 新增部署、备份恢复、安全基线文档。
- `.env.deploy.example`、`.gitignore`、`.dockerignore`
  - 提供部署变量模板。
  - 忽略真实 `.env.deploy`，避免密钥误提交或进入构建上下文。

## 对应功能

- 运维可以通过 `/metrics` 和 `/health` 快速判断 API、数据库、Redis 状态。
- GitHub Actions 能在合并前验证 C 包关键后端能力和前端构建。
- 部署同学有明确的环境变量、启动、回滚、备份恢复和安全基线文档。
- 主 compose 不再使用危险占位默认值，缺少部署变量时会在解析阶段失败。

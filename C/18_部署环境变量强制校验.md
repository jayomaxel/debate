# 部署环境变量强制校验

## 本轮目标

解决主 `docker-compose.yml` 被误当成本地一键启动入口使用时，因占位默认值和旧数据卷状态不一致，导致 `api` 假性启动失败的问题。

## 修改文件

- `docker-compose.yml`
- `.env.deploy.example`
- `.gitignore`
- `.dockerignore`
- `ops/deploy.md`

## 修改逻辑

- `docker-compose.yml`
  - 将 `POSTGRES_PASSWORD`、`DATABASE_URL`、`SECRET_KEY`、`PUBLIC_BASE_URL`、`ALLOWED_ORIGINS` 改为必填环境变量
  - 如果没有通过 `--env-file .env.deploy` 或等价方式显式传入，Compose 会在解析阶段直接报错并停止
- `.env.deploy.example`
  - 提供一份可复制的部署变量模板，避免手写时漏项
- `.gitignore` / `.dockerignore`
  - 忽略真实 `.env.deploy`
  - 避免部署密钥被误提交到仓库，或被带入 Docker 构建上下文
- `ops/deploy.md`
  - 明确主 compose 必须配合 `.env.deploy` 使用
  - 明确“不带环境文件会被直接拦截”是预期保护，不是故障

## 对应功能

- 主部署入口不再依赖危险的占位默认值
- 本地历史数据库卷与错误密码组合时，不会再拖到 `api` 启动阶段才暴露问题
- 部署同学可以直接从示例文件复制出 `.env.deploy`

## 验证方式

- 不带环境文件执行 `docker compose config`
  - 预期：直接报缺少必填变量
- 带示例环境文件执行 `docker compose --env-file .env.deploy.example config`
  - 预期：配置可正常解析

## 结论

这次修复后，根目录 `docker-compose.yml` 的职责被收紧为“显式部署入口”，不会再和本地开发联调入口混用。
本地联调仍应优先使用 `docker-compose.dev.yml` 或 `docker-compose.local.yml`。

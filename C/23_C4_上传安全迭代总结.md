# C4 上传安全迭代总结

## 本轮目标

补齐截图反馈中的 C4：新增 `upload_guard.py` 和 `upload_security.py`，把上传安全从业务路由中抽出为统一网关。

## 修改逻辑

- `api/utils/upload_security.py`
  - 定义上传策略表，按路径和 HTTP method 命中具体上传入口。
  - 覆盖知识库文档、头像、ASR 音频、教师辩论支撑材料。
  - 对上传文件执行扩展名、MIME、魔数和大小校验。
- `api/middleware/upload_guard.py`
  - 作为全局中间件读取 multipart body 并解析上传文件。
  - 合法文件放行给下游路由。
  - 非法文件返回冻结的 `UploadGuardErrorContract`。
  - 对上传放行、拦截、扫描失败记录审计事件。
  - 暴露 Prometheus 计数器 `debate_upload_guard_total`。
- `api/main.py`
  - 挂载 `UploadGuardMiddleware`，让真实应用入口启用上传网关。
- `api/tests/test_upload_guard.py`
  - 覆盖合法 PDF、非法扩展名、非法 MIME、伪造魔数、头像大小限制、合法音频和教师支撑材料入口。

## 对应功能

- 上传入口具备统一安全拦截，不再依赖各业务路由自行判断。
- 前端收到稳定的错误码和 `request_id`，便于展示和排查。
- 下游业务仍可正常读取中间件检查过的 multipart 文件。
- 上传行为进入审计和 metrics，便于后续运营排查。

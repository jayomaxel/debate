# C1 登录会话迭代总结

## 本轮目标

补齐截图反馈中的 C1：真实登录会话基本完成，并确认 `session_id`、服务端会话、`logout`、`logout-all`、refresh 绑定 session 全部落地。

## 修改逻辑

- `api/services/auth_service.py`
  - 登录、管理员登录、刷新都会生成并复用 `session_id`。
  - access token 和 refresh token payload 都带上 `session_id`。
  - 登录和刷新统一返回冻结合同字段，同时保留旧前端兼容字段。
  - 新增当前 session 吊销和全量 session 吊销服务方法。
- `api/utils/security.py`
  - 增加服务端 session 存储、读取、续期、吊销逻辑。
  - Redis 优先，Redis 不可用时降级到进程内内存。
  - 增加旧 access token 吊销兼容逻辑，处理历史无 `session_id` token。
- `api/middleware/auth_middleware.py`
  - 受保护接口在 JWT 校验后继续校验服务端 session 状态。
  - 把 `_auth_session_id` 和 token payload 挂到当前用户对象，供路由层使用。
- `api/routers/auth.py`
  - `POST /api/auth/login` 和 `POST /api/auth/refresh` 使用冻结响应合同。
  - 新增 `POST /api/auth/logout`。
  - 新增 `POST /api/auth/logout-all`。

## 对应功能

- 登录后服务端会生成可追踪、可吊销的 session。
- refresh 不再只相信自签 JWT，必须绑定仍然 active 的服务端 session。
- 当前设备登出后，原 access token 和 refresh token 都会失效。
- 全设备登出后，该用户所有已登录 session 都会失效。
- 对历史旧 token 做兼容处理，避免一次性打断已有链路。

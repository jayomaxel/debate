# 教师端教学设计与能力雷达图实现说明

## 1. 审查结论

原有系统已经具备教师创建辩论、预约辩论、结构化 `config_meta`、报告和雷达图的基础能力，但缺少“班级教学设计上传—抽取校正—辩题推荐—版本追溯”的闭环；报告中的聚合口径也未明确隔离 AI 与真实学生。

本次补齐了教学设计版本中心、候选辩题生成及历史引用链路，并把教师端团队能力雷达调整为真实人类学生口径。未发现可安全复用的教学设计上传实现，因此没有保留重复入口；创建辩论和预约辩论复用同一套结构化配置规则。

## 2. 业务链路

```text
班级教学设计（版本化）
  ├─ 原文件与原始文本
  ├─ 自动抽取结果、置信度、缺失项、证据片段
  └─ 教师校正结果
          ↓
当前教学设计 + 本次活动重点
          ↓
AI 候选辩题（失败时规则降级）/ 手工辩题
          ↓
教师确认 → 普通辩论或预约辩论
          ↓
config_meta 固化教学设计版本 ID 与活动重点
          ↓
辩论完成 → 有效发言与评分
          ↓
教师端真实学生能力雷达图
```

关键原则是“AI 推荐、教师确认”。系统不会把模型生成结果直接当成最终教学内容，也不会用模型不可用作为阻断教师建赛的理由。

## 3. 后端实现

### 3.1 数据模型与迁移

新增 `class_teaching_designs`，以 `(class_id, version_number)` 保证班级内版本唯一，保存：

- 文件名、文件路径、文件类型；
- `extracting / ready / needs_review / failed` 状态及错误信息；
- 原始文本、自动抽取数据、教师校正数据；
- 置信度、缺失字段、字段证据片段；
- 当前版本标记、创建人和时间。

迁移文件：`api/alembic/versions/015_add_class_teaching_designs.py`。

### 3.2 教学设计服务

`TeachingDesignService` 负责：

- 校验 PDF/DOCX 与 10MB 上限；
- 抽取 PDF 页面文字及 DOCX 段落/表格文字；
- 识别课程目标、知识点、章节主题、重点难点、能力目标、年级、课时和备注；
- 保留原始抽取，另存教师校正值；
- 管理班级版本和当前版本；
- 调用已配置模型生成候选辩题；模型失败时生成 3 个规则候选题并返回 `rules_fallback`。

### 3.3 教师接口

| 方法 | 接口 | 用途 |
|---|---|---|
| GET | `/api/teacher/classes/{class_id}/teaching-designs` | 查询版本历史 |
| GET | `/api/teacher/classes/{class_id}/teaching-designs/current` | 查询当前版本 |
| POST | `/api/teacher/classes/{class_id}/teaching-designs` | 上传并抽取新版本 |
| PUT | `/api/teacher/teaching-designs/{version_id}` | 保存人工校正 |
| POST | `/api/teacher/teaching-designs/{version_id}/activate` | 切换当前版本 |
| POST | `/api/teacher/classes/{class_id}/topic-recommendations` | 基于版本和活动重点生成候选题 |

所有接口均检查教师对班级的访问权限；推荐接口还检查版本是否属于目标班级以及抽取是否失败。

### 3.4 历史记录

普通创建和预约创建都会把以下信息写入辩论的 `debate_config_meta`：

```json
{
  "mode": "teaching",
  "teaching_design_version_id": "创建时采用的版本ID",
  "activity_focus": {
    "chapter_focus": "章节重点",
    "training_focus": "训练目标",
    "classroom_scene": "课堂场景"
  },
  "assignment_policy": "ai_recommend_then_confirm"
}
```

因此后来上传 V3 或把 V1 切回当前，都不会改变已经创建的辩论对 V2 的引用。教师端历史列表会显示保存的版本 ID；以后需要展示完整版本内容时，可用该 ID 查询对应快照。

## 4. 前端实现

### 4.1 教学设计中心

新增教师菜单“教学设计”，支持班级切换、上传、状态/置信度/缺失字段展示、字段校正、抽取依据、历史版本和当前版本切换。

### 4.2 创建与预约

创建页和预约页共用候选辩题面板：

- 自动读取班级当前教学设计；
- 可填写本次章节重点、训练目标和课堂场景；
- 展示候选题难度、推荐理由、目标/知识点映射和可辩性；
- 采用后仍允许教师编辑；
- 未配置教学设计或推荐失败时保留手工输入；
- 编辑历史辩论时同步回显保存的版本和活动重点。

## 5. 能力雷达图口径

### 5.1 纳入条件

同时满足以下条件才进入教师端人类能力统计：

1. 参赛关系指向真实存在且 `user_type=student` 的账号；
2. `speaker_type=human`；
3. 发言内容非空，`is_valid_for_scoring=true`，转写状态不是失败；
4. 评分通过 `speech_id` 关联到该发言，并且 `participation_id` 与学生参赛记录一致。

AI 发言、未知身份、无内容、无效/转写失败发言、孤立评分均排除。发言时长图仍可同时展示人类和 AI，因为它表达的是过程占比，不是学生能力。

### 5.2 汇总算法

团队值采用“先学生内平均，再学生间等权平均”：

```text
某学生某维得分 = 该学生所有有效评分的平均
团队某维得分 = 所有已评学生该维平均分的平均
```

这样不会让发言次数更多的学生获得更高权重。

### 5.3 五维映射

| 评分字段 | 展示维度 |
|---|---|
| `logic_score` | 逻辑建构 |
| `argument_score` | AI 核心知识运用 |
| `response_score` | 批判思维 |
| `persuasion_score` | 语言表达 |
| `teamwork_score` | AI 伦理科技素养 |

接口同时返回参与评估学生数、有效人类发言数、排除的 AI 发言数及是否存在人类能力数据。没有人类数据时返回 `ability_scores=null`、`overall_score=null`，前端显示空态或 `--`，不显示 0。

## 7. 部署与验证建议

1. 备份数据库并执行 Alembic 迁移 `015`。
2. 确认上传目录对 API 进程可写，并限制反向代理请求体大小不低于 10MB。
3. 配置模型 API；即使未配置，规则降级和手工辩题仍可用。
4. 按《教师端教学设计测试说明》执行页面、接口、权限和历史追溯测试。
5. 重点抽查旧辩论报告：旧数据没有 `human_ability` 时前端仍使用兼容口径；新报告优先使用后端人类统计。

## 8. 已知边界

- 当前数据模型没有统一的 `seed/demo` 或软删除来源字段，无法精确给出“排除模拟记录数”；现阶段以真实学生账号、参赛关系、有效发言和评分证据链排除孤立/模拟数据，`excluded_demo_record_count` 暂为 0。若未来引入演示数据，应在用户、发言或评分模型增加明确来源字段后纳入过滤与计数。
- 当前抽取是文本型 PDF/DOCX，不包含 OCR。扫描件会明确失败，不会用猜测内容生成辩题。
- 前端构建需在具备 Node.js 和项目依赖的环境中执行；本次环境未安装 Node.js，已完成后端编译、接口相关测试和前端静态结构检查。

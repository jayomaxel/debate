# P1-4 基础限流

## 本轮目标

为登录、上传和高频报告入口补上基础限流，减少暴力尝试和异常高频调用对服务的冲击。

## 修改文件

- `api/middleware/rate_limit.py`
- `api/main.py`
- `api/tests/test_rate_limit.py`
- `api/services/audit_service.py`

## 代码逻辑

- 在 `api/middleware/rate_limit.py` 定义路径级限流策略，按 bucket、时间窗、阈值和身份解析方式进行匹配。
- 优先覆盖：
  - `/api/auth/login`
  - 上传入口
  - 报告相关 POST/PUT 接口
- 限流实现优先用 Redis 计数，Redis 不可用时退化为进程内窗口计数。
- 被限流时返回稳定的 `429` 响应，并带：
  - `Retry-After`
  - `X-RateLimit-Limit`
  - `X-RateLimit-Remaining`
- 限流命中写入审计日志和 Prometheus Counter。
- 在 `api/main.py` 挂载全局中间件。
- 在 `api/tests/test_rate_limit.py` 验证正常请求可通过、超阈值会被拦截且响应头完整。

## 对应功能

- 登录口令爆破和上传滥用有了最小防护。
- 前端可以通过响应头做节流提示或重试等待。
- 限流命中可被审计和监控，而不是静默失败。

## 风险/未完成项

- 当前策略是基础版，没有区分租户、班级或更细粒度业务对象。
- 多实例部署时建议优先保证 Redis 可用，以获得跨实例一致的限流结果。

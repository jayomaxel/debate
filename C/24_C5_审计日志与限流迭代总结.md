# C5 审计日志与限流迭代总结

## 本轮目标

补齐截图反馈中的 C5：建立审计日志服务和基础限流能力，让登录、配置、上传、管理员操作等关键动作可记录、可查询、可限流。

## 修改逻辑

- `api/services/audit_service.py`
  - 提供统一 `AuditService.record_event()` 和 `AuditService.list_events()`。
  - 事件结构复用冻结后的 `AuditLogEventContract`。
  - Redis 优先写入，Redis 不可用时降级到进程内缓存。
  - 记录 Prometheus 计数器，便于运行态观测。
- `api/routers/auth.py`
  - 登录成功/失败、refresh 成功/失败、logout、logout-all、ws ticket 签发写入审计。
- `api/routers/admin.py`
  - 配置修改、管理员密码修改写入审计。
  - 新增 `GET /api/admin/audit/events` 查询最近审计事件。
- `api/middleware/rate_limit.py`
  - 定义路径级限流策略，覆盖登录、上传和报告再生成入口。
  - Redis 计数优先，Redis 不可用时使用进程内窗口计数。
  - 限流命中返回 `429`，并设置 `Retry-After`、`X-RateLimit-Limit`、`X-RateLimit-Remaining`。
  - 限流命中写入审计事件。
- `api/main.py`
  - 挂载 `RateLimitMiddleware`。
- `api/tests/test_audit_service.py`
  - 覆盖登录审计、失败登录审计、配置更新审计、审计查询接口、管理员密码修改审计。
- `api/tests/test_rate_limit.py`
  - 覆盖登录限流、上传按用户身份限流、响应头返回。

## 对应功能

- 管理端可以查询最近安全关键事件。
- 登录爆破、上传滥用、报告高频重算有基础限流保护。
- 审计和限流都能在 Redis 不可用时降级工作，避免核心接口直接不可用。
